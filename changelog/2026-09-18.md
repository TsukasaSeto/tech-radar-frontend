### `practices/ai-agent/claude-code.md` Rule #12（Claude Code hooks を3層で設計）
hook の `matcher` がツール種別（`Write|Edit`）に絞られていると、AI が別ツール（`Bash`）経由で目的を達成した場合に hook が一切発火しない実測（0/5）を追加。同じ一文を CLAUDE.md に書いた場合は 25/25 で遵守された対比データも記録。「初動の判断に効かせたいルールは CLAUDE.md、事後検知は hook」という使い分け原則を補強。

> "ルール無しの5回は当然0行。でも残り15回は全部3行で、中身も `wrote:a.txt` / `wrote:b.txt` / `wrote:c.txt` で完全に一致していました"
> ([AIへの指示書に書いたルールは25回とも守られた。同じ一文をフックに移したら、5回とも一度も届かなかった](https://zenn.dev/numarn/articles/claude-md-rule-vs-hook-injection-handson), セクション "「指示書は守られない」は、私の手元では再現しなかった") ※2026-09-18に実際にfetch成功

### `practices/ai-agent/claude-code.md` Rule #22（ネスト型サブエージェントのフロントマター設計）
`tools:` フロントマターで `Bash(git diff:*)` のようにサブコマンドパターンで絞り込んでも、実際には Bash ツール全体が渡ってしまう実測を追加。`disallowedTools` はツール単位で丸ごと除去する一方、許可リスト側の `tools` ではパターンが実効的なフィルタにならない非対称性を明記し、コマンド単位の絞り込みは `PreToolUse` hook に委ねる代替策を追記。

> "`Bash(git diff:*)` と書いた行が、Bash を丸ごと渡していた。"
> ([サブエージェントの tools で Bash を絞ったつもりになっていないか](https://qiita.com/yurukusa/items/9466eaccf8e4c26cd137), セクション 検証結果) ※2026-09-18に実際にfetch成功
