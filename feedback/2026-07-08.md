### 1. 未マージ Routine PR が一定数を超えたら、新規 PR 起票を抑制し「バックログ警告」に切り替える

- **現状の記述**: 「main の最新コミットSHAを取得する」とだけ書かれており、未マージ PR の存在を確認する手順がない
- **提案する変更**: Step 2 に「GitHub MCP で `practice-update/*` および `seen-json-update/*` ブランチの open PR 件数を確認する。3件（1.5日分）を超えて未マージの PR が存在する場合、通常の Practice Update PR に加えて、changelog に『未マージPRバックログ: N件、最古はYYYY-MM-DD』を明記し、本文に警告セクションを追加する」を追記する
- **理由**: 今回4件のバックログ＋1日分の完全欠落を検出した。これは human 側のレビュー速度がRoutineの生成速度に追いついていないシグナルであり、Routine自身が気づいて明示しない限り気づかれにくい
- **想定リスク**: なし（情報追加のみ、実行自体は妨げない）
- **優先度**: 高

### 2. dev.to/Medium 由来の「精読したが統合できなかった」候補を構造化リストとして持ち越す仕組みを追加する

- **提案する変更**: changelog の却下表に `統合先候補ファイル` 列を追加する（例: 今回の `dev.to/david_shibley/...` なら `api-client/error-handling.md（要検討）`）。次回セッションは Step 1（既存プラクティス読み込み）の直後に、直近3日分の changelog からこの列を grep し、優先精査キューとして扱う

- **想定リスク**: changelog のフォーマットがやや複雑になる。ただし表の列追加程度で実装コストは低い
- **優先度**: 中
