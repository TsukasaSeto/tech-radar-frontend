## プロンプト改善提案（3件）

### 1. Step 3 の取得経路を `releases.atom` + rss2json に変える
- **対象セクション**: 処理フロー > Step 3: 公式リポジトリの差分確認
- **現状の記述**: 「以下を `GitHub MCP → raw.githubusercontent.com` の順で取得」
- **提案する変更**: 「vercel/next.js と microsoft/TypeScript は `https://github.com/{owner}/{repo}/releases.atom` を rss2json 経由で、facebook/react は `https://raw.githubusercontent.com/facebook/react/main/CHANGELOG.md` を取得する（GitHub MCP はセッションのリポジトリ外を読めない）」
- **理由**: 今回この経路で 3 リポジトリとも取得できた（feedback/2026-11-10.md 提案 2 の検証結果）
- **想定リスク**: rss2json のレート制限で段階2 のフィードと競合する
- **優先度**: 中

### 2. Stripe の日付判定を `stripe.dev/blog/feed` で行う
- **対象セクション**: HTML特殊処理ソース > Stripe Engineering Blog > 取得手順 3
- **現状の記述**: 「公開日確認: 一覧HTMLに `[Month DD, YYYY]` 形式」
- **提案する変更**: 「公開日確認: 一覧 HTML に日付がないため、`https://stripe.dev/blog/feed`（RSS）の pubDate で判定する。feed が取得できない日は一覧の記事 URL を個別に取得して日付を確認する」
- **理由**: 今回一覧 HTML から日付を 1 件も抽出できなかった。feed は 200 で 128 件取得できた
- **想定リスク**: feed は engineering 以外のトピックも含むため、一覧で抽出した URL と突き合わせる必要がある
- **優先度**: 中

### 3. AllOrigins 段階B / C の成功条件に challenge ページの除外を加える
- **対象セクション**: アクセス経路の絶対指示 > 段階3 / 段階4 / 個別記事取得 段階B・C

- **提案する変更**: 「成功条件: HTTP 200（get は `.status.http_code == 200` も）で、本文が Cloudflare challenge（`<title>Just a moment...</title>`）でないこと」
- **理由**: 今回 raw でも 200 + challenge が返った（2026-11-10 の提案は get のみ対象だった）
- **想定リスク**: なし
- **優先度**: 中
