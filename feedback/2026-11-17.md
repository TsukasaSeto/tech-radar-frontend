## プロンプト改善提案（2件）

### 1. OWASP の個別記事取得は raw の原稿を段階A とする
- **対象セクション**: 標準RSSソース定義 > 公式ブログ・本家 / 個別記事取得
- **現状の記述**: `段階A: 直接WebFetch（記事URL）`（OWASP も同じ扱い）
- **提案する変更**: OWASP 行に「コミットの link は github.com で 403 になるため、コミットタイトルからチートシート名を特定し `https://raw.githubusercontent.com/OWASP/CheatSheetSeries/master/cheatsheets/<Name>.md` を段階A として取得する。`_seen.json` にはコミット URL を記録する」と追記する
- **理由**: 今回 3 件のコミットすべてで段階A が 403。raw の原稿は 200 で、判定に必要な本文がそのまま得られた
- **想定リスク**: チートシート名がコミットタイトルから特定できない更新（複数ファイル変更など）は従来どおり段階B/C
- **優先度**: 中

### 2. Step 3 の取得先に raw / nextjs.org のフォールバックを明記する
- **対象セクション**: Step 3: 公式リポジトリの差分確認
- **現状の記述**: `以下を GitHub MCP → raw.githubusercontent.com の順で取得`
- **提案する変更**: 「GitHub MCP / api.github.com はこのリポジトリ以外に届かないため、Next.js は `https://nextjs.org/feed.xml`（既に段階1 で取得済み）の release 記事、TypeScript は `https://devblogs.microsoft.com/typescript/feed/` を代替とする（許可ドメイン追加が必要なら env に反映）」に置き換える
- **理由**: Releases は raw に存在しないため、記述どおりの順で試しても取得できない
- **想定リスク**: devblogs.microsoft.com が許可ドメイン外なら env 側の変更が要る
- **優先度**: 低
