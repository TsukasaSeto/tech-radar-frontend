## 新たに観察した問題

### 1. `_seen.json` の drop 検知チェックが、末尾要素のカンマ変化を誤検知する
- **種類**: ツールの癖（想定外挙動）
- **発生箇所**: Step 5 の `git diff --cached _seen.json | grep '^-  "' && { echo "ERROR..."; exit 1; }` チェック
- **詳細**: 新規URLを配列末尾に追記すると、旧ファイルで最後の要素だった行（カンマなし）が新ファイルでは非最後尾になり `,` が付与される。これが unified diff 上で「削除1行＋追加1行」として現れ、`grep '^-  "'` は「削除された行」として旧ファイル末尾のURLの行にマッチしてしまう。実際にはURLの削除は発生しておらず、`diff <(jq -r '.[]' base | sort) <(jq -r '.[]' new | sort) | grep '^<'` のようなURL集合ベースの比較では drop なしと確認できた。
- **想定リスク**: このチェックを字面通り実行すると、正常な追記のたびに「ERROR: URL deletion」が出て毎回コミットを中断させることになり、drop検知が形骸化（誤検知に慣れて見逃す）するリスクがある。
- **提案する変更**: SKILL.md / プロンプトの Step 5 のコマンド例を「`git diff --cached _seen.json | grep '^-  "'` の単純な行diffではなく、`diff <(jq -r '.[]' base.json | sort) <(jq -r '.[]' new.json | sort) | grep '^<'` のような集合比較を正とする」よう明記し、行diffベースのチェックは補助情報（末尾カンマ変化は無視してよい旨の注記付き）として扱うよう修正する。
- **優先度**: 中（自動判定が誤って毎回止まる/誤って通す、のどちらの方向にもブレうる曖昧さがあるため）

- **種類**: 採用基準の迷い
