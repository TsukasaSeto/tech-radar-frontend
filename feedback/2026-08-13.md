### 1. `_seen.json` の必須検証コマンド（Step 5: commit直前チェック）に構造的な誤検知がある
- **種類**: ツール / プロンプト記述
- **発生箇所**: 「_seen.json の仕様 > 削除禁止ルール」ステップ5（`git diff --cached _seen.json | grep '^-  "'`）
- **詳細**: append-only で配列末尾にURLを追加すると、従来の最終要素の行は「末尾カンマなし」から「末尾カンマあり」に変わるため、テキストdiff上は「旧: カンマなしの行が削除され」「新: カンマありの同一URL行が追加される」という1行の削除+1行の追加として現れる。今回も `"https://linear.app/now/how-we-built-linear-agent"`（カンマなし）が `-` 側に、`"https://linear.app/now/how-we-built-linear-agent",`（カンマあり）が `+` 側に出た。指示通り `grep '^-  "'` を素朴に実行すると、実際には何も削除していないのに毎回 ERROR 判定になってしまう
- **影響**: 今回はこの1件のみで、事前の集合ベース比較（`diff <(jq -r '.[]' base|sort) <(jq -r '.[]' new|sort) | grep '^<'`）で実際の削除がないことを確認できたため誤って中断はしなかったが、Step 5 の文字列だけを機械的に実行する運用だと毎回 false positive で PR 起票が止まりかねない
- **影響（定量）**: 検証ステップ1回分、判断に数分の追加確認が発生
- **再現性**: 高い（配列に1件でも追記すれば必ず起きる構造的な問題。過去のchangelogでこの誤検知が報告されているかは未確認だが、append-onlyという設計上ここ数日の全run で潜在的に発生していたはず）
- **プロンプト改善提案**:
  - **対象セクション**: 「_seen.json の仕様 > 削除禁止ルール」ステップ5
  - **現状の記述**: `git diff --cached _seen.json | grep '^-  "' && { echo "ERROR: URL deletion in staged diff"; exit 1; }`
  - **提案する変更**: 単純な `-` 行検出ではなく、削除された行からURL文字列だけを抽出し、追加された行のURL集合に同じ文字列が存在するかを確認してから ERROR 判定する。例: `git diff --cached _seen.json | grep '^-  "' | sed -E 's/^-  "(.*)",?$/\1/' | while read -r u; do git diff --cached _seen.json | grep -F "\"$u\"" | grep '^+' >/dev/null || echo "REAL DROP: $u"; done` のように、削除候補が追加側にも同一URLとして存在する（＝末尾カンマ付け替えのみ）場合は無視する
  - **理由**: 現状の検証はStep 2-3の集合ベース比較で真の削除は既に検出できているため、Step 5は「本当に安全か」の二重チェックとして機能すべきだが、現状は形だけの文字列一致で毎回誤爆する
  - **想定リスク**: 抽出ロジックのバグで本物の削除を見逃す可能性があるため、Step 2-3の集合比較を主、Step 5を副とする位置づけは変えない
  - **優先度**: 中
