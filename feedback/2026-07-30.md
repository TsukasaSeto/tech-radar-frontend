### 4. `_seen.json` の実ファイルスキーマが本プロンプト記載のスキーマと異なる
- **種類**: プロンプト記述
- **発生箇所**: 「`_seen.json` の仕様 > スキーマ」セクション
- **詳細**: プロンプトは `{"version": "1.0", "updated_at": ..., "entries": [{"url", "fetched_at", "status"}, ...]}` という object スキーマを記載しているが、実際の `_seen.json`（origin/main時点）は URL 文字列のみのフラット配列（`["https://...", "https://...", ...]`）だった。過去のcommitログ（`chore: update _seen.json with N new URLs...`）を見ても一貫してフラット配列運用がされており、object スキーマへの移行は行われていない。本Routineの「_seen.json の仕様 > 削除禁止ルール」セクションに書かれているjqコマンド例自体はフラット配列前提で実態と一致しているため、実害はなく今回もそのコマンド例通りに処理した。
- **影響**: 実害なし（削除禁止ルールのjqコマンドは実態と一致していたため、対応に迷わなかった）
- **再現性**: 継続的（スキーマ記載は過去のRoutineでも実態と食い違っていたと推測されるが、今回のセッションで初めて明示的に確認・記録した）
- **プロンプト改善提案**:
  - **対象セクション**: 「`_seen.json` の仕様 > スキーマ」
  - **現状の記述**: object + `entries[].status` 形式のスキーマ例
  - **提案する変更**: 実態に合わせてフラット配列スキーマ（`["url1", "url2", ...]`）に書き換え、`status`（adopted/read_skipped/fetch_failed）の区別は`_seen.json`自体には持たせず changelog 側でのみ記録する運用である旨を明記する
  - **理由**: プロンプトのドキュメントと実装が乖離していると、将来的にどちらが正か判断に迷うRoutine実行が発生しうる
  - **想定リスク**: なし（ドキュメント修正のみ）
  - **優先度**: 低
