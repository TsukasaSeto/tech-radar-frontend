- **影響**: 未試行36ソース分の新着記事を取りこぼしている可能性がある（実害の定量化はできない。次回以降そのソースが試行された際に36h窓バッファで拾える可能性はある）

### 2. `_seen.json` の flat array 実装は fetch_failed の24h再試行猶予を表現できない（既知問題の再発）
- **種類**: プロンプト記述
- **発生箇所**: 「`_seen.json` の仕様」、Medium react個別記事（React Compiler 1.0記事）が403で本文取得に失敗した際
- **詳細**: 2026-07-30 feedback で既に指摘済みの問題（`_seen.json` の実スキーマが object+status ではなく flat array）が、今回は「fetch_failed の URL をどう扱うべきか」という具体的な意思決定の場面で再浮上した。flat array に単純追加すると、この記事は今後二度と候補に上がらなくなり、プロンプトが定める「24時間後に再試行可能」という fetch_failed の意味論が壊れる。今回は判断としてこの1件を `_seen.json` に追加しなかった（一時的な403は翌日以降に再試行できるようにするため）。
- **影響**: 実害は限定的（1件のみ）。ただし今後 403/5xx 等の一時的失敗が増えると、都度「追加するか否か」を手動判断する必要があり、判断がぶれるリスクがある
- **再現性**: 継続的（2026-07-30 feedback item 4 と同一問題。今回は「実際に対応が必要になった」という新しい具体例）
- **プロンプト改善提案**:
  - **対象セクション**: 「`_seen.json` の仕様 > スキーマ」（2026-07-30 feedbackの提案を再掲・優先度を引き上げ）
  - **提案する変更**: flat array 運用を正式仕様として明文化した上で、「fetch_failed（一時的アクセス失敗）の URL は `_seen.json` に追加しない」というルールを明記する。もしくは、別ファイル（例: `_fetch_failed.json`、タイムスタンプ付き）を新設して24h retry を実現する
  - **想定リスク**: 別ファイル方式は実装コストが増える。「追加しない」方式は運用コストが低いがシンプルすぎて情報が失われる
  - **優先度**: 高（2日連続の指摘のため引き上げ）
