### 2. `_seen.json` の「スキーマ」セクションが実装と乖離している（新規発見）
- **対象セクション**: `_seen.json の仕様 > スキーマ`
- **現状の記述**: `{"version": "1.0", "updated_at": ..., "entries": [{"url", "fetched_at", "status"}]}` という object 形式のスキーマが明記されている
- **提案する変更**: リポジトリの実ファイルは一貫して `["url1", "url2", ...]` という文字列の flat array であり、`version`/`updated_at`/`entries`/`status`（adopted/read_skipped/fetch_failed）フィールドは実在しない。同じプロンプト内の「削除禁止ルール」セクションの jq レシピ（`. + $new | reduce ...`）は逆に flat array を前提にしており、実態と一致している。「スキーマ」セクションを flat array 前提に書き換えるか、削除して「削除禁止ルール」側の記述に一本化すべき
- **理由**: 「スキーマ」セクション通りに実装しようとすると（本セッションでも一瞬 `jq '.entries'` を試みてエラーになった)、存在しないフィールドへのアクセスで失敗する。`status: adopted/read_skipped/fetch_failed` によるトラッキングが仕様上は謳われているが実際には一度も実装されておらず、「24時間以内はfetch_failedを再試行しない」等のロジックも実質機能していない
- **想定リスク**: 今から `status` 付きスキーマに実際に移行する場合、3800件超の既存URLをどう扱うか（全て `status` 不明として扱うか）の移行設計が必要になる。単純にドキュメントを実態に合わせるだけなら副作用はない
- **優先度**: 高
