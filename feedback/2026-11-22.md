## プロンプト改善提案（3件）

### 1. AllOrigins の成功条件にチャレンジページ検出を追加する
- **対象セクション**: アクセス経路の絶対指示 > 段階3 / 個別記事取得
- **現状の記述**: 「成功条件: HTTP 200、レスポンスボディが空でない」
- **提案する変更**: 「成功条件: HTTP 200、レスポンスボディが空でなく、`<title>Just a moment...</title>` や `Enable JavaScript and cookies to continue` を含まない（Cloudflare チャレンジページは失敗として次の段階へ進む）」
- **理由**: Medium の個別記事で段階B が 200 + チャレンジページを返し、成功と誤判定しかけた
- **想定リスク**: 低（文字列一致の誤検知はまれ）
- **優先度**: 中

### 2. AllOrigins get の `contents` が data URI の場合のデコードを明記する
- **対象セクション**: アクセス経路の絶対指示 > 段階4
- **現状の記述**: 「URL構造: https://api.allorigins.win/get?url={ENCODED_LIST_URL}」のみ
- **提案する変更**: 「`.contents` を取り出す。`data:...;base64,` で始まる場合は `sed 's/^data:[^,]*,//' | base64 -d` でデコードしてから XML として解析する」
- **理由**: OWASP の Atom が base64 の data URI で返った
- **想定リスク**: なし
- **優先度**: 低

### 3. Netflix を段階1 スキップ表から外すか、段階1 を 1 回だけ試す
- **対象セクション**: 段階1 をスキップするソース
- **現状の記述**: 「Netflix Tech Blog | HTTP 503（2026-05-16〜2026-05-20 で5回連続） | 段階2 (rss2json)」
- **提案する変更**: 「スキップ表のソースも、段階2 が 429 の日は段階1 を 1 回だけ試す」
- **理由**: rss2json の 429 が常態化しており、スキップ表のソースは段階2 から始めると取得機会がほぼない。feedback/2026-11-16.md では Netflix の段階1 成功が報告されている
- **想定リスク**: 段階1 の試行が 1 回増えるだけ
- **優先度**: 中
